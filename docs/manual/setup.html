How access works

Three things decide what a person sees: their roles, their branches, and whether their account is active.

  1. User
    Who is signing in?
    email + password
  2. Roles
    What may they do?
    permissions
  3. Branches
    Where may they do it?
    warehouses & documents
  4. Menus & buttons
    What they actually see
    checked on the server
Hiding is not the only protection.Every page and every save checks the permission again on the server, so a user cannot reach a screen by typing its address.

Global setup

Under Setup → Global Setup.

1

Company settings

Setup → Global Setup ► Company settings

Company name (shown as "Licensed to"), currency code (e.g. PHP) and address (shown on the sign-in page).

2

Branding

Setup → Global Setup ► Branding

The system's identity: name, tagline, sign-in headline, logo (also the browser tab icon), typefaces and the full colour palette. A live preview shows the result before saving and warns about hard-to-read colour pairs. Reset to defaults brings back the built-in look.

3

Branches

Setup → Global Setup ► Branches

Sites, regions or company units, each with a short code (e.g. MNL) used in document numbers. Every warehouse belongs to a branch; documents belong to the branch of their warehouse.

  • Users see only the branches assigned to them on their user page.
  • The permission "See all branches" lifts that limit.
4

Document numbering

Setup → Global Setup ► Document numbering

The format of every numbered document: prefix, number of digits, whether the counter is per branch and whether it restarts each year. Changes apply to new documents only.

Default formats: MOV stock movements · INV sales invoices · PAY payments received · CSH cash book · JE journal entries · PO purchase orders · RR receiving reports · APV supplier bills · CV payments made. Example: INV-MNL-2026-000001.
5

Inventory/WMS lists

Setup → Inventory/WMS ► Item Types · Item Classes

Classification lists: item types (Finished Goods, Raw Materials…) and a tree of item classes under each. Used by record types built in Custom modules.

Security

Under Setup → Security.

6

Users

Setup → Security ► Users

Name, email, password, active, roles and branches. Deactivating a user signs them out everywhere at once. You cannot deactivate yourself.

7

Roles

Setup → Security ► Roles

A role is a named set of permissions, ticked per module. Give people roles, not individual permissions. Starting roles: Administrator (everything), Inventory Clerk, Sales Clerk, Finance and Accountant. Add your own for each job.

8

Audit log

Setup → Security ► Audit log

Every change: who, when, what, with the values before and after. Each entry is chained to the previous one by a fingerprint. Verify the log has not been tampered with checks the whole chain and reports the first entry that was altered, if any.

How to

The common jobs, step by step.

Add a new employee

  1. Setup → Security ► Users → New.
  2. Enter name, email and a starting password (8+ characters).
  3. Tick their roles and the branches they work in.
  4. Ask them to sign in and keep the password private.

Separate duties (maker / checker)

  1. Create roles such as "Purchasing Clerk" (create POs, receive) and "AP Officer" (post bills, pay).
  2. Do not give one person both posting and approval rights on the same documents.
  3. Keep "Close and reopen periods" to the accountant.

Open a new branch

  1. Setup → Branches → New, with a short code.
  2. Inventory → Warehouses → New, in that branch.
  3. Assign the branch to its users.
  4. Load its opening stock (see Inventory).

Someone leaves the company

  1. Open their user and untick Active. They are signed out at once.
  2. Their past work keeps their name in documents and the audit log.
